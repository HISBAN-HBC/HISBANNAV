# HISBAN Navigation (حُسبان)

**HISBAN Navigation MVP**
**Status: Experimental / Research Prototype**

HISBAN Navigation تقدير موقع تقريبي من قياسات الشمس (ارتفاعها وسمتها) والزمن العالمي (UTC). يعطي موقعاً مع عدم يقين، ويكشف عن حالة الملاحة وحالة الحساس بصورة منفصلة. ليس بديلاً عن GNSS، ولا يُعرض موقعاً حين لا تسمح الهندسة بذلك.

> **تنبيه:** النتائج الحالية محاكاة واختبارات برمجية. لم تُثبَت دقة ميدانية بعد. أول جلسة على هاتف حقيقي هدفها التحقق من أن إعادة التشغيل تطابق التسجيل، وليس قياس الدقة.

## الحالة الحالية

- **منجز ومختبَر:** الفلك الشمسي، والشبكة الهرمية، والمُقدِّر (Levenberg–Marquardt)، وقابلية الرصد، والتشخيص (الانحراف والشواذ)، وخط الأنابيب الموحّد، وتسجيل الجلسات (schema v2) وإعادة تشغيلها على مستويين.
- **منجز ولم يُجرَّب على جهاز:** صفحات Android/Chrome: شاشة المعايرة، وشاشة التصويب. المنطق مختبَر بواجهات مزيفة، والصفحات لم تعمل بعد على هاتف حقيقي.
- **تجريبي:** مزوّدات الحساسات الحقيقية (`sensors/browser.js`). لا تعرف بعد اتفاقية إطار Chrome على الجهاز الفعلي. وتتحقق شاشة المعايرة من هذه الاتفاقية.
- **غير منجز:** جودة البوصلة (Chrome لا يكشف حالة معايرتها)، وخطأ التصويب البشري، والانكسار الجوي، وخط الأفق.

## تشغيل الاختبارات

لا يحتاج المشروع إلى أي حزمة خارجية. يلزم Node.js 22 أو أحدث.

```bash
npm test
```

يعرض النتيجة النهائية كالتالي: `# pass 180` و`# fail 0`.

## تشغيل الواجهات محلياً

من جذر المشروع:

```bash
python3 -m http.server 8000
```

ثم افتح:

- `http://localhost:8000/ui/index.html`: لوحة المختبر على بيانات Mock أو ملف جلسة محفوظ.
- `http://localhost:8000/ui/calibration.html`: معايرة اتجاه الكاميرا (تحتاج حساسات).
- `http://localhost:8000/ui/aim.html`: تصويب الشمس وتسجيل الجلسة (تحتاج حساسات).

> الحساسات تتطلب HTTPS على الهاتف. الخادم المحلي يكفي للحاسوب فقط، ولاختبار الهاتف استخدم GitHub Pages.

## النشر على GitHub Pages (للهاتف)

1. ارفع المشروع إلى مستودع، وفعّل Pages من الفرع الرئيسي (المجلد الجذر).
2. افتح على هاتف Android بمتصفح Chrome:
   - `https://<اسم-المستخدم>.github.io/<اسم-المستودع>/ui/calibration.html` **أولاً**.
   - ثم `https://<اسم-المستخدم>.github.io/<اسم-المستودع>/ui/aim.html`.

المعايرة تُحفظ على الجهاز نفسه (localStorage)، وصفحة التصويب تستعملها تلقائياً، وتُسجَّل مع الجلسة.

## بنية المجلدات

| المجلد | الدور |
|---|---|
| `core/` | دوال أساسية: المسافات والسمت والقبلة وزاوية حُسبان |
| `engine/` | الموقع الشمسي (NOAA، تقريبي منخفض الدقة) وتقاطع خطوط العرض والطول |
| `grid/` | الشبكة الهرمية (HGRD): خلايا 5° |
| `matcher/` | ترجيح الخلايا بـ χ²، والتحسين الهرمي |
| `estimator/` | Levenberg–Marquardt للمعاملات (φ, λ, b_A) |
| `observability/` | مصفوفة فيشر وعدم يقين الموقع بالكيلومتر وحالة الملاحة |
| `diagnostics/` | الانحراف D، والشواذ (O، t، D₋ᵢ)، وحالة الحساس |
| `pipeline/` | **القلب التشغيلي**: تحقق، مطابقة، تحسين، تقدير، قابلية رصد، تشخيص، ناتج موحّد |
| `research/` | الجلسة (schema v1 و v2)، والتسجيل، والتصدير، وإعادة التشغيل |
| `sensors/` | عقود الحساسات، ومزوّدات Mock وReplay وBrowser، وحساب التصويب (`attitude.js`, `aim.js`) |
| `ui/` | الواجهات: `index.html`، `calibration.html`، `aim.html`، والمنطق المختبَر بجانبها |
| `montecarlo/` | مختبر المحاكاة المنفصل، واختبار التكافؤ الذهبي مع المُقدِّر |
| `docs/` | المواصفة (`SPEC-MVP.md`)، وبروتوكول الجلسة الميدانية (`FIELD-PROTOCOL.md`) |

`montecarlo/` مختبر منفصل وليس جزءاً من المنتج. اختبار التكافؤ يضمن أن مُقدِّر المنتج يعطي النتائج نفسها.

## تسجيل جلسة (schema v2) وإعادة تشغيلها

الجلسة تحفظ القراءات الخام، والقياسات المشتقة، ونتائج الخط، وحالة الجهاز والمعايرة. كل قياس مرتبط بفهارس قراءاته الخام، حتى تُعاد بناؤه وتُقارن.

```js
import { createSession, addRawReading, addMeasurement, addResult,
         serializeSession, parseSession, replaySession } from "./research/index.js";

let s = createSession({ sessionId, appVersion, algorithmVersion, algorithmConfig, device, calibration });
s = addRawReading(s, "imu", rawImuRecord);          // تُسجَّل كل قراءة خام، حتى غير المتاحة
s = addMeasurement(s, measurement, { imu: [0, 1, 2] }); // قياس مرتبط بنافذة عينات
s = addResult(s, estimate);                          // نتيجة الخط عند عدد القياسات الحالي

const text = serializeSession(s);                    // ملف JSON ثابت
const loaded = parseSession(text);
replaySession(loaded, { level: "raw" });             // يعيد بناء القياسات من الخام، ثم الخط، ثم يقارن
```

- **`raw`:** يعيد بناء القياسات من القراءات الخام، ويتحقق منها، ثم يعيد تشغيل الخط. هذا هو المعيار الأساسي.
- **`measurement`:** يعيد تشغيل الخط على القياسات المجمّعة فقط.
- **الملفات القديمة (schema v1)** تُقرأ وتُعاد على مستوى القياسات.

صفحة التصويب تنزّل الجلسة كملف JSON، وصندوق «فحص إعادة التشغيل» فيها يقرأ ملفاً ويعرض النتيجة.

## بروتوكول أول جلسة ميدانية

انظر `docs/FIELD-PROTOCOL.md`. الترتيب:

**المعايرة ← التصويب ← تسجيل schema v2 ← تقدير HISBAN ← مقارنة GNSS ← إعادة التشغيل**

معيار النجاح الأول: نتيجة الهاتف ونتيجة إعادة التشغيل متطابقتان. الدقة تُدرس بعد ذلك.
